## What is aifindr.org?

A community-driven, open-source directory of AI tools across 12 categories. Tools are submitted through the online form, reviewed in the admin dashboard, and published to the directory. The site also runs a blog/CMS, contributor profiles, email notifications and scheduled maintenance jobs.

## Free Backlinks for Contributors

Approved submissions earn three permanent **dofollow** backlinks:

| Source | URL | Notes |
|--------|-----|-------|
| GitHub Pages listing | `kbmjj123.github.io/aifindr.org/listings/[category]/[slug]` | Generated from a source file in this repo (`docs/listings/`); live via GitHub Pages |
| Tool detail page | `aifindr.org/tools/[category]/[slug]` | "Submitted by" link (`submitter_site`) |
| Contributor profile | `aifindr.org/contributors/[username]` | Personal website link |

> The online form is the supported submission path. On approval we generate the GitHub Pages listing automatically — see [Known gaps](#known-gaps).

## Tech Stack

| Layer | Technology |
|-------|-----------|
| Framework | Nuxt 4 (Vue 3, TypeScript, Nitro) |
| Styling | Tailwind CSS v4 via `@tailwindcss/postcss` + CSS variables (dark theme) |
| SEO | `@nuxtjs/seo` (sitemap, robots, runtime OG images) |
| Database | Cloudflare D1 (`aifindr-db`) |
| Cache / Media | Cloudflare KV (`CACHE`) / R2 (`CDN`, served from `https://cdn.aifindr.org`) |
| Runtime & deploy | A single Cloudflare Worker (`nitro preset: cloudflare_module`), custom domains `aifindr.org` + `www` |
| Auth | GitHub OAuth + JWT |
| Package manager | pnpm 10 |

**Architecture:** pages and the ~45 `/api/*` Nitro endpoints ship in the same Worker (`.output/server/index.mjs` + `.output/public`). Most pages are server-rendered on the edge; only `/admin/**` and `/blog*` run with `ssr: false`. Tool data and Markdown bodies live in D1, not in Markdown files.

## Getting Started

### Prerequisites

- Node.js (a recent LTS) with pnpm 10 enabled
- A Cloudflare account if you need D1/KV/R2 bindings (Wrangler can emulate them locally)

```bash
git clone https://github.com/kbmjj123/aifindr.org.git
cd aifindr.org
pnpm install
pnpm dev            # http://localhost:3000
```

`wrangler.toml` supplies the D1/KV/R2 bindings; in local dev Nitro emulates them through Wrangler. Local secrets go into `.dev.vars` / `.dev.vars.local` (git-ignored). `.env.example` only lists the `R2_*` variables used by the image migration script.

### Configuration

Public values live in `wrangler.toml` under `[vars]`:

| Variable | Purpose |
|----------|---------|
| `API_BASE` | Public site/API base URL |
| `R2_PUBLIC_URL` | Public CDN base (`https://cdn.aifindr.org`) |
| `GITHUB_CLIENT_ID` | GitHub OAuth app client ID |
| `ADMIN_GITHUB_IDS` | Comma-separated GitHub IDs allowed into `/admin` |

Secrets are set with `wrangler secret put <NAME>`: `TURNSTILE_SECRET`, `GITHUB_CLIENT_SECRET`, `JWT_SECRET`, `RESEND_API_KEY`, `GITHUB_BACKLINK_TOKEN`, `GITHUB_PR_TOKEN` (PR comment + squash merge; optional — publishing still works without it), `LEMONSQUEEZY_WEBHOOK_SECRET`, `SITE_URL`. The authoritative list is the `CloudflareEnv` interface in `server/utils/env.ts`.

### Database

```bash
wrangler d1 execute aifindr-db --remote --file=./schema/init.sql
# Optional: load the submission-site directory dataset (generated by the ETL script below)
wrangler d1 execute aifindr-db --remote --file=./schema/seed-submission-sites.sql
node scripts/build-submission-sites.mjs   # regenerate seed + cleaning report
```

`schema/init.sql` defines 16 tables: the original 9 (`tools`, `tool_tags`, `users`, `email_logs`, `generated_articles`, `published_links`, `posts`, `post_translations`, `custom_fields`) plus 7 for the open submission-site directory (`submission_sites`, `site_categories`, `submission_lists`, `submission_list_items`, `site_relations`, `submission_list_changelog`, `submission_site_reports`). `schema/reset.sql` is for resetting a local/dev database.

### Build & Deploy

```bash
pnpm build
wrangler deploy
```

Four cron triggers are declared in `wrangler.toml` and dispatched by `server/plugins/scheduled.ts` (daily ops, link checker, monthly report, newsletter).

## Submitting a Tool

Use the [online form](https://aifindr.org/submit). Provide the tool name, website, category, pricing, a short description and optional details; the submission enters `pending` status and is reviewed in `/admin` before publication.

Guidelines: short, factual descriptions; no promotional superlatives; the tool must be publicly accessible and actively maintained; one tool per submission.

Content for each listing is produced locally: the `aifindr-tool-intake` project skill (see `.claude/skills/`) runs a verification pipeline over the submitted domain — deterministic screening, zero-LLM evidence probing, and a real-browser hands-on run — then writes `data/tool-pages/<host>.md` from the observed evidence. Listings that cannot be verified are recorded as such and are never published as verified.

> The older "create a Markdown file under `content/tools/` and open a PR" path is **not currently active** — that directory and its sync script no longer exist in this repo.

## Data & API

All data access goes through Nitro handlers in `server/routes/api/`, using `getEnv(event).DB`. Front-end code calls them through `composables/useApi.ts` (SSR uses `useRequestFetch` in-process to avoid Worker self-fetch; CSR uses `$fetch` with a Bearer token).

Endpoint groups: tools & search, submit & upload, stats/click/view, auth, admin (review, tools, posts, users, broadcast, submission lists), blog & contributors, public submission-site directory & lists, sitemap, cron, webhooks (GitHub / Lemon Squeezy). See `api-spec.yaml` for a request/response reference, and the source files for the authoritative signatures.

## Submission-Site Directory

`/backlink-sites` is a free, open directory of 848 third-party platforms that accept product or website submissions, with search and filters for pricing, dofollow links, domain rating, approval speed and topic. `/submission-lists` publishes 18 generated lists; `/backlink-sites/data` explains the data sources and fields and carries a correction form. The directory does not offer dataset downloads or JSON/CSV export.

These are **not** the AI tools in the `tools` table — they are a separate D1 dataset (`submission_sites` and six companion tables). Facts come from a public directory snapshot dated 2026-11-16. Each row carries structured facts (`accepts_product_types` on 796 rows, typical `approval_time` on 339) plus the full quoted content from SubmitMap's platform pages (847 rows, shown with attribution): source lead, eligibility, what-you-get, how-to steps, requirements, gotchas, rejection reasons and FAQ, along with the platform's icon, homepage screenshot and OG image. All explanatory text, topic tags and list definitions are written by aifindr.org, and third-party outbound links are `nofollow`. Rewritten originals live in `docs/rewritten/*.jsonl` and are mirrored into `rw_*` columns with automatic fallback to the attributed source text; platform images are hosted on `cdn.aifindr.org` in `r2_*` columns. See the rewrite spec and plan under `docs/superpowers/`. New platforms added via `/admin/submission-lists` only enter lists once their fields are complete; list membership is recalculated from the database by `server/utils/submissionLists.ts`.

The generated `schema/seed-submission-sites.sql` is committed, so deploying does not require the raw scrape. To rebuild it, place the local scrape in `docs/res-v2/` (git-ignored; the script falls back to `docs/res/` when it is absent) and run `node scripts/build-submission-sites.mjs`. The same run also writes `reports/submission-sites-cleaning.json` and a local-only `reports/submission-sites-snapshot.json` for internal ETL scripts; neither is published as a download. Before importing a seed that contains `accepts_product_types`, run `schema/migrate-submission-sites-v2.sql` once against the existing database. Re-importing the seed is safe: admin-edited rows, manual tags, confirmed relations and list curation are preserved; refresh the lists once afterwards to restore pinned positions.

**Ongoing additions happen in `/admin/submission-lists`**: add a single platform, paste a JSON array for bulk import (up to 200 rows), search and edit any existing row to complete missing facts, hide/restore entries, create new lists with a validated filter DSL, and curate pinned/included/excluded members. All three write paths share `server/utils/submissionSiteWrite.ts`; incomplete rows are held at `needs_info`, and saving a row automatically recalculates every rule-based list. Topic categories are maintained the same way and appear in the public directory filter as soon as they are used.

## Known gaps

- The GitHub Pages listing is generated into `docs/listings/[category]/[slug].md` on approval; it requires the `GITHUB_BACKLINK_TOKEN` secret. Submissions go through the online form only.
- Legacy PRs are enriched locally with the `aifindr-tool-intake` skill and published through `POST /api/admin/publish-pr` (admin-only): active insert + PR traceability (`pr_number`/`pr_url`) + listing page + B-03/F-02 emails + a PR comment with the three backlinks + squash merge. Set `GITHUB_PR_TOKEN` (Issues:write + Contents:write) for the comment/merge steps; without it those steps are skipped but publishing still succeeds. Migrate older databases with `schema/migrate-tools-pr.sql`.
