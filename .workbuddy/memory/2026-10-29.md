## 试跑暴露的 8 个真实缺陷（全部已修，都是}{实测踩出来的，不是设计推演）

1. **假阳性**：aitoolsradar 点 "Run search" 后冒出 22 张 256px 图片被判成 AI 产物。
   → 图片必须 ≥320px 才算产物。
2. **点错按钮**：imagetoimage 上 "Remove source image"（清空）与 "Generate image" 打平。
   → 按钮打分加入：距输入位距离、是否在 nav/footer、文案词数、—12 惩罚 control 类词。
3. **inChrome 模糊匹配**：`[class*=header]` 命中了包裹整页的容器，全站按钮统一扣 12 分，
   打分信号被抹平（imagedescriber 的 "Start Analysis" 被压到 6 分）。
   → 只保留语义标签 `nav, footer, [role=navigation], [role=contentinfo]`，**刻意不含 header**（常被用来包 hero）。
4. **缺前置勾选**：vocalseparator 的 "Remove vocals" 要等「我拥有这段素材」勾上才启用。
   → `tickConsents` + 自定义控件兜底 `tickRightsControls`；后来该站又把原生 input 换成自定义控件，证明兜底层必须有。
5. **只抓 `<img>` 漏掉整个音频品类**：vocalseparator 的产物是两个 `<audio>`。
   → `persistArtifact` 覆盖 图片/音频/视频/文字，页面内 fetch 失败再退 node 侧裸 GET。
6. **结果容器太宽**：`main`/`article` 把整页营销文案当成生成结果写进报告。
   → 收紧到严格的结果类名，加 6000 字符上限，并要求「之前几乎没有、之后有了」。
7. **供应商名单缺产物 CDN**：`replicate.delivery` 没在名单里，而它才是真正的调用证据。
8. **规划错优先级**：vedicastrologychart 有 4 个必填文本框（姓名/城市/日期/时间），
   却因为误匹配到一个「拖拽区」(实为 topbar dropdown) 去上传图片。
   → plan 优先级改为 真实 file input > 文本框(多字段全填) > contenteditable > 拖拽区；
   拖拽区需同时满足 尺寸≥120x80 且 文案含 upload/drop/drag 等词。
